## 2. The essay

Final: **Overture** (385w) · **Dissection** (1,400w) · **Response** (668w) ·

invalid CSS selector, and `querySelector('#2')` throws.

when the title lost its gerund. A meta-refresh plus `rel="canonical"` stub remains at

## 4. Changes applied site-wide

### 4.1 Mobile bottom sheet

Tapping a superscript below 900px opens the note in a sheet rather than jumping to the
foot of the page. Dismiss on backdrop tap, grip tap, swipe down, or Esc. Background
scroll locked, `prefers-reduced-motion` respected, focus returned on close.

Implemented as a delegated listener that intercepts the existing anchor and calls
`preventDefault`; the original markup and numbering script are untouched. Desktop
behaviour is unchanged — the sheet computes to `display: none` above 900px and the
margin sidenotes still reveal on click.

**On the no-JS question.** An earlier version of this guarded the endnotes list behind
a JS-set class, on the reasoning that it was a fallback. That reasoning was wrong and
was removed: the superscript markers *and* the endnotes list are both generated by the
script, so with JS off there are no notes at all. There is no no-JS path to preserve,
and there never was, on any of the three essays.

### 4.2 Print stylesheet

Endnotes are hidden on screen at all widths but reclaimed for print on their own page.
Nav, mobile bar, sheet, sidenotes and return arrows suppressed; 20mm page margin; black
on white; orphan/widow control; no break inside an endnote or immediately after a
heading.

External URLs are expanded after their link text, so a printed copy keeps its
citations. Internal anchors excluded.

Verified by rendering each essay to PDF: 10, 6 and 30 pages, notes present on their own
page with URLs intact, superscript markers still rendering in the body so notes can be
matched.

### 4.3 Port

Both blocks ported to *Age of Generation* (51 notes) and *Walk to the Heavens* (6). The
three blocks are **byte-identical across all three files, verified by hash**, and are
marked `portable block` in each. Change one, change all three.

Tested on each page independently: sheet opens with the correct note, content and links
intact, scroll locked, no jump to the foot, closes cleanly; desktop unaffected; print
correct.

## 5. Fault: 15-minute silent deployment stall

**Symptom.** Commit `0e31f49` pushed successfully; the site continued serving the
previous commit for over fifteen minutes with no error surfaced.

**Diagnosis.** Ruled out the obvious causes in order — `origin/main` was at the right
SHA, and the pushed blobs contained the changes (`git show origin/main:<path>`);
cache-busted requests still returned old content, ruling out the CDN; a string unique
to the new commit was absent from the live page, confirming the *whole commit* was
undeployed rather than partially cached. No Liquid syntax in any new file, which is the
usual cause of a Jekyll build failure.

**Fix.** Added `.nojekyll`. The same commit deployed in **30 seconds**.

**Why it is the right fix, not just a nudge.** Pages runs every push through Jekyll by
default. This site uses no Jekyll feature — no front matter, layouts, includes or
Liquid. The build step was therefore pure risk, and its failure mode is silent: a
failed build is indistinguishable from a slow one from the outside. `.nojekyll` removes
the step. It must not be deleted.

Documented in `HANDOVER.md` §7, with the cache-buster diagnostic.
